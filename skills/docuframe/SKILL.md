# docuframe

Give it a topic or a script, get a finished documentary or explainer film in the style you pick.

Everything on screen is drawn by code from data (Skia, in Python): titles, photos with camera
moves, maps, numbers, quotes, timelines. The same project renders the same film every time, a new
narration re-times the whole film by itself, and nothing on screen is generated by an image model.

Run every command as `python scripts/docuframe.py <command>` from this skill's folder (or
`docuframe <command>` if the package is installed). Paths below are relative to the project folder.

## What "done" means

A film is done when the user has, in `<project>/out/`:

1. `<name>_16x9.mp4` (and/or 9:16, 1:1) — rendered, with narration, played through once by you via stills
2. `captions.srt` and `captions.vtt` — match the narration word for word
3. `youtube/` — 3 titles, a description with chapters, sources and credits, tags, 3 thumbnails, an upload checklist
4. `manifest.json` — sources, image licences, attribution lines, fonts, voice, settings, re-render command
5. `check.md` with no ✗ items, or the remaining ones explained to the user

and you have told them, in plain words, what you checked and anything you could not fix.

## First run

1. `python scripts/docuframe.py doctor` — checks Python, the engine, ffmpeg, fonts, voice, disk,
   memory, and paths with spaces or non-Latin letters. Every ✗ line comes with the exact command to fix
   it for the user's system. Run the command (ask first for system installs such as ffmpeg), then
   run doctor again. `doctor --fix` installs the Python parts.
2. If Python itself is missing: Windows `winget install Python.Python.3.12`, macOS
   `brew install python@3.12`, Linux `sudo apt install -y python3 python3-pip`. Then new terminal.
3. The local voice downloads ~120 MB once (Apache-2.0 model). Fonts download on first use (SIL OFL).

If the user cannot run commands (Claude app without a terminal), tell them about the one-click cloud
option in the README (GitHub Codespaces) instead of guessing.

## Quick mode and director mode

- **Quick mode** (default when the user says "just make it", gives a one-line topic, or is clearly
  not technical): ask at most one question (usually the angle or the length), pick the style
  yourself (see the menu), write everything, review the approval stills yourself, then render.
  Tell the user which choices you made in one short list at the end.
- **Director mode** (when the user wants control, says "let me approve", or the film is long or for a
  client): stop for approval at three points — script + fact sheet, approval stills, final film.

Either way, record the approval: `make --project P --approve` (director) or `make --yes` (quick).
The manifest keeps it as proof of human creative direction.

## Workflow

1. **Start the project.** `new <name> [--template history-short] [--style S] [--format 16:9]`.
   Never start from a blank folder: the template shows every file's shape.
2. **Research (topic input).** Search reliable sources (encyclopaedias, archives, official sites,
   reputable news). Write `facts.json`: one entry per claim with id, the claim in plain words, and
   1–3 sources (publisher, title, URL). Prefer two sources for any number. If you cannot find a
   source, the claim does not go in the film. If the user gave a script, build the fact sheet from
   the script's claims and mark unsourced ones for the user instead of inventing sources.
3. **Script.** Write `script.json`: `title`, `lang`, and `takes` (chapters) of `lines`. Each line has
   `text` (what captions show), `spoken` (how the narrator says it — numbers and years in words),
   `facts` (ids) or `"opinion": true`. Structure: a hook that states the payoff inside 10 seconds,
   then chapters, then a close. One idea per line, 8–25 words. See `references/script.md`.
4. **Fact pass.** `check --project P --no-frames` — every line with a number or claim must link to a
   sourced fact. Fix or flag before any voice is made (a re-voice costs time).
5. **Voice.** `voice --project P` (local voice), or `voice --project P --audio their_read.wav`
   (user's recording, split into lines by its pauses), then `narration --project P`, then optionally
   `align --project P` (word timing; needs faster-whisper). See `references/voice.md` for languages.
6. **Photos.** List images in `photos.json`. `archive find "..."` finds openly licensed archive
   images; `archive fetch --project P` downloads them with licence and credit. The user's own photos:
   put them in `assets/photos/` and set `"license": "own"`. Then `assets --project P`.
7. **Plan the beats.** Write `film.json`: style, format, and `beats` — each beat a scene from the
   library, the line it belongs to, the spoken word it lands on (`"at"`), and a `"source"` for any
   number, map or chart. Pacing: a new beat every 4–8 s, a pattern interrupt (chapter card, map,
   quote, big number) every 30–60 s. See `references/scenes.md` for every scene and its fields.
8. **Approval stills — the checkpoint before heavy rendering.** `render --project P --stills auto`
   writes one still per beat and `out/stills/sheet_<format>.jpg`. Look at every still yourself
   (see the self-review loop). Fix, re-render stills. Then show the sheet to the user (director mode)
   or continue (quick mode).
9. **Render.** `render --project P` (1080p, chunked, resumable; `--draft` for a fast half-size
   preview; `--format 9:16` for vertical). A 20-minute film takes a while: tell the user the ETA the
   command prints. If it stops, run the same command again — finished chunks are kept.
10. **Sound, captions, check, package.** `sfx --project P` (effects synthesised from the film's own
    cues), `mix --project P [--music file-you-own.mp3]` (voice on top, music ducked, -14 LUFS), then
    `captions --project P`, `check --project P`, `package --project P`. Render again after `mix` so
    the film carries the mixed soundtrack.
    Or run 5–10 in one go with `make --project P` (stops at approval) / `make --project P --yes`.
11. **Shorts and dubbing (optional).** `shorts --project P` cuts a 9:16 version of the hook from the
    same project. Dubbing: copy the project, translate `script.json` (keep line ids and facts), set
    `lang`, translate on-screen text in `film.json`, then voice → narration → render. Timing follows
    the new narration automatically. See `references/dubbing.md`.
12. **Deliver.** Send the files, summarise in 3–5 lines, list what the check could not verify.
    `share --project P` makes a preview clip and post text if they want to post about it.

## Style menu

One line each; pick by subject and tone. `styles` lists every installed pack.

- **evidence-board** — dark cork wall, pinned photos, red string, one continuous camera. True crime, history, investigations, biographies.

More packs are added as data in `styles/<name>/style.json`; their `rules.md` says when to use them.
If the user names a look you don't have, pick the nearest pack and say so — never imitate a named
channel, studio or artist.

## Rules (and why)

- **Never invent facts, numbers, quotes or sources.** Viewers, platforms and lawyers check. Missing
  information is asked for or left out; a claim without a source is flagged, not narrated.
- **Quotes are verbatim** with who said it and when; if you only have a paraphrase, don't use quote cards.
- **Every on-screen number, map and chart carries a source line** (`"source"` on the beat). The
  description lists every source; image credits are added automatically.
- **Only openly licensed or user-owned images.** The archive command refuses non-commercial and
  no-derivatives licences because the user may monetise the film.
- **No generated images for text, numbers, maps, labels, logos or diagrams.** They come out wrong;
  code draws them right.
- **No real brands' logos or trademarks** unless the user supplied them as their own.
- **Time hits to words, not seconds** (`"at": "word"`): the film re-times itself when the voice changes.
- **Vary episodes in a series** (different openings, scene mix, accents): YouTube does not monetise
  channels whose videos look template-made (policy checked 2026-11-20, see README).
- **Synthetic voices are disclosed** in the description; the upload checklist says when YouTube's
  "altered or synthetic content" box applies (realistic people/events or a cloned real voice).
- **Ask before installing system software** and never run scripts fetched from the internet.

## Self-review loop

Before showing anything and after every render: look at the stills (`out/stills/`, `out/check/`).
For each still ask: is the hero of this beat readable and inside the frame? Is anything cut off,
overlapping, too small, or mid-motion blur? Does the text say exactly what the narration says?
Is the source line there for data? Is RTL text joined and right-to-left? Then run `check`.
Fix (film.json first, style overrides second), re-render the stills, look again. Stop after 5
rounds and report what remains, with the still that shows it.

## Delivery and manifest

`package` writes `out/youtube/` and `out/manifest.json`. The manifest lists inputs (hashes),
style, format, voice, timing method, sources, image licences and credits, fonts, approvals,
outputs (hashes) and `rerender` — the one line that rebuilds the film. Tell the user: the film is
theirs, including for commercial use, subject only to the attribution lines in the manifest.

## Will not do

Refuse briefly, offer a nearby safe version if there is one:
- instructions for weapons, explosives, or anything that helps someone hurt people
- content that sexualises minors, or encourages self-harm
- harassment or targeting of private individuals; defamatory claims about real people
- deceptive impersonation of real people or brands; fake news made to look real
- "documentaries" presenting invented events, quotes or numbers as true

## Troubleshooting

| Symptom | Fix |
|---|---|
| `ffmpeg is not installed` | `doctor` prints the install line for this OS; open a new terminal after installing |
| Render stopped (crash, sleep, Ctrl+C) | Run the same `render` command: finished chunks are kept |
| Render very slow / machine freezes | `render --workers 1`; close other apps; `--draft` to preview |
| Text in Arabic/Persian shows boxes or separate letters | `doctor` (font fetch); keep `"lang"` set in film.json |
| A beat shows an empty frame | its `"at"` word is near the end of the line: anchor it earlier |
| `"word" is not in the spoken text` | `at` must match the `spoken` text (numbers in words) |
| `photo P01 is not prepared` | add it to photos.json, then `archive fetch` / `assets` |
| Colours look washed out in a player | the files are tagged BT.709 TV range; use a current player (VLC, browsers) |
| Windows: `PermissionError` when writing | antivirus locks new files; docuframe retries — if it persists, exclude the project folder |
| Voice speaks the language with an accent | that language is experimental in the local voice: use `--audio` with a native recording |

## Limits

- Local voice: native quality in English, Spanish, French, Hindi, Italian, Portuguese, Japanese,
  Chinese; other languages are accented drafts — use the user's recording for publishing.
- Word timing without `align` is an estimate (~150–250 ms).
- Archive search covers Wikimedia Commons; other archives need the item URL and its rights line.
- Rendering is CPU-only: expect roughly real-time ×2–4 at 1080p on a 4-core laptop; long films take a while.
- One style pack ships in this version; see the README for the roadmap.
